# NetHackJP 翻訳作業 指示ファイル

この文書は、NetHackJP の日本語化作業における翻訳方針、スタイル、および実務上の知見をまとめたものです。ビルド手順やプロジェクト管理などの技術的な運用については `.github/copilot-instructions.md` を参照してください。

## 1. 目的と対象

- **目的**: ユーザー向けメッセージの日本語化を、安全かつ一貫性を保って進める。挙動を変えず表示文言のみを改善する。
- **優先対象**: 画面表示されるメッセージ（`You(...)`, `You_feel(...)`, `pline(...)` など）。
- **対象外**: コメント、ログ、内部診断用文言（`impossible(...)`, `error()` など）。
- **README**: `README.JP` は `README` の翻訳とし、プロジェクト進捗などは記載しない。

## 2. 翻訳の基本方針

### 文体・スタイル
- **常体**: 「だ・である」を基本とする。
- **敬語（ですます調）**: ユーザーへの質問文（確認・入力促進）は**ですます調**を使用する。例:
  - 「本当に削除しますか？」→ 「本当に削除してもよろしいですか？」
  - 「何をする？」→ 「何をなさいますか？」
- **時制**:
  - 叙述は過去形を優先（例: 〜した、〜だった）。
  - 継続的な状態や感覚は現在形（例: 〜している、〜が聞こえる）。
  - 現在の状態を示すものは現在形 (例: ～している)
  - 短時間の音・感覚は過去形（〜感じた）、長時間のものは現在形（〜感じる）を推奨。
- **ニュアンス**: 原文の意味を尊重し、過剰な意訳や情報の追加を避ける。ただし自然な日本語になることを重視する。

### 自然さ優先の実装基準（2026-05 追記）
- **優先順位**: 「壊さない」だけでなく、表示時に不自然でないことを最優先で確認する。
- **完成文で判定**: 置換対象のリテラル単体ではなく、分岐・接頭辞・引数展開後の完成文で自然さを確認する。
- **直訳テンプレートを避ける**: 英語語順（`at/around/by` など）を無理に保持せず、日本語として自然な文型へ組み替える。
- **語形変化依存を避ける**: `vtense()`, `makeplural()`, `an()` など英語活用前提の組み立ては、日本語表示では使わず文全体を日本語で構成する。
- **品質ゲートを二段化**: ①コンパイルが通ること ②表示文が自然であること（助詞・語順・視点・統一語彙）を確認して完了とする。

### 記号・表記
- **文末記号**: 互換性のため、半角 `.`, `!`, `?` を維持する。
- **UI整合性**: 既存のUI訳語（職業名・種族名・ステータス名など）と整合させる。

## 4. フォーマット指定子の厳守

以下はできるだけ変更しない（個数、順序、型、対応する引数式）。

## 5. 翻訳の実務知見

- **最終表示文の確認**: 複数のリテラルや分岐で構成される文は、結合後の全体像で自然か確認する。
- **pline系関数**: 文言以外の位置制御や履歴制御（`pline_dir` 等）には触れない。
- **補助関数の活用**: `Monnam()`, `body_part()`, `Tobjnam()` 等の返り値を前提に語順を調整する。
- **接頭辞の自動付与**: `You_hear()`, `You_feel()`, `You_see()` 等は主語を自動付与するため、リテラル側で主語を重複させない。
- **不自然な連結の回避**: `隠し%s` などのテンプレートは、展開後の語（扉、通路等）との連結が自然か確認する。

### 部位名翻訳（body_part/mbodypart）の指針（2026-05 追加知見）
- **種別配列ベースで訳語を決める**: `mbodypart()` の一次配列（`humanoid_parts`, `jelly_parts`, `bird_parts` など）が想定する身体構造に合わせて訳語を選ぶ。英語トークン単体だけで機械的に訳さない。
- **部位スロットの意味を維持する**: `HAND/HANDED` は「手に相当する器官」、`LIGHT_HEADED` は「ふらつき状態」のように、スロットの意味を崩さない。見た目が自然でも意味がズレる訳（例: 状態語を部位名にする）は避ける。
- **`HANDED` 系は種に応じた器官名へ**: `clawed`, `hooved`, `winged`, `tentacled` などは一律の語に潰さず、表示文で自然になる器官名（例: 鉤爪/ひづめ/翼/触手）を優先する。
- **`LIGHT_HEADED` 系は文脈で決める**: `You_feel("ちょっと%s気がした.", ...)` のような文脈で使われるため、`めまいがする` のような述語的表現を使う。名詞的で不自然な語（例: 回転感）は避ける。
- **翻訳はテーブル駆動で管理する**: `jp_translate_bodypart_name()` は `if` 連鎖ではなく `{en, ja}` テーブルで一元管理する。重複定義・優先順依存のバグを防ぎ、保守性を高める。
- **未定義語は必ずフォールバックする**: 未登録トークンは `jp_bodypart_default(part_id)` へ確実にフォールバックさせ、表示破綻を防ぐ。

### モンスター名連結（2026-05 追加知見）
- **表示文では `l_monnam()` を優先**: 日本語テンプレートで `%s` の直後に助詞（`は/を/に/へ/が/の/と/から`）が続く場合、`mon_nam()/Monnam()` だと英語冠詞混入（`The ...`）が起きやすい。表示用途は `l_monnam()` を第一候補にする。
- **`y_monnam()` は文脈で使い分ける**: 「あなたの〜」の意味が必要な文（所有関係を強調する文）では `y_monnam()` を維持し、不要なら `l_monnam()` へ寄せる。
- **複合連結は機械置換しない**: `%s%sから` / `%sは%s%sから` / `%sを%s%sから` は語順崩れを起こしやすいため、文脈ごとに手動で自然文へ組み替える。
- **英語冠詞ヘルパの連結を避ける**: `just_an()` や `a/an` 前提の中間文字列を日本語文へ流用しない。必要なら `trapbuf` のように日本語名詞句を先に組み立ててから本文に渡す。
- **確認の優先順**: 戦闘（`uhitm/mhitu`）・拘束解除（`apply/trap`）・騎乗（`steed`）・移動制限（`hack`）を優先して表示確認する。

### オブジェクト名 (Method C) の補足指針
- **内部IDと表示名を分離する**: `include/objects.h` は upstream 英語を維持し、Lua `des.object({ id = "..." })` や各種ルックアップの互換性を守る。
- **日本語表示は `src/obj_jp.c` に集約する**: アイテムの日本語名・未識別外観は `obj_jp_names[]` / `obj_jp_descrs[]` と `jp_item_name()` / `jp_item_descr()` で管理する。
- **表示系のみ差し替える**: `src/objnam.c` などユーザー向け表示で `jp_item_name()` / `jp_item_descr()` を使い、検索・同定・wish・Lua ID解決の内部ロジックは英語名参照を維持する。
- **外見名と真名の分離**: `OBJ(name, desc)` の `name` と `desc` は意味が異なるため、同一語にまとめない。
- **`oc_descr_idx` の扱いに注意**: 未識別外観は shuffle の影響を受けるため、`jp_item_descr()` は `objects[otyp].oc_descr_idx` 経由で参照する。
- **`#if 0` 定義を混ぜない**: `objects.h` 上で無効化されている ID（例: DEFERRED 呪文）を `obj_jp.c` に入れるとビルドエラーになるため除外する。
- **語彙方針**: JNetHack-3.6.7 の語彙を基本としつつ、個別指定がある用語（例: `へんげの杖`）を優先する。

### 地形名表示 (Method C) の補足指針（2026-05 追加知見）
- **`defsyms[]` 本体は英語維持**: `src/drawing.c` の家具判定や `src/sp_lev.c` の `appear_as.str` 比較が `defsyms[i].explanation` の英語を前提にしている。テーブル本体を日本語化すると special level 互換を壊しやすい。
- **表示は専用ヘルパへ分離**: 地形名は `jp_cmap_explanation()` / `jp_terrain_name()` のような表示専用経路で日本語化し、内部比較・ID解決は英語のまま維持する。
- **`dfeature_at()` の戻り値を比較キーにしない**: 表示文字列を日本語化した後に `"open door"` / `"doorway"` / `"pool of water"` / `"altar "` などの英語文字列比較を残すと回帰しやすい。判定は `levl[x][y].typ`、`doormask`、`is_pool()`、`IS_ALTAR()` など型ベースで行う。
- **壁の描画差分は表示名を統一**: `S_vwall` 〜 `S_trwall` は見た目の差（線分・角・T字）であり、地形種別としては同じ壁なので表示名は `壁` に統一してよい。

### 内部キー文字列と表示文の分離（汎用ルール）
- **英語キーは内部用途として維持する**: 文字列が変数キー・比較キー・ID解決キーとして参照される場合（例: wish/Lua ID、パーサー入力、テーブル照合、`strcmp`/`strncmp` 比較）は、キー文字列そのものを日本語化しない。
- **表示専用データを別テーブルで持つ**: 日本語表示が必要な場合は、アイテム (`obj_jp`)・モンスター (`mon_jp`) と同様に表示専用データを別管理し、内部キーと分離する。
- **表示は専用ヘルパー経由に限定する**: 呼び出し側は `jp_*_for_display()` 系のヘルパーを経由して表示語を取得し、内部ロジック（検索・照合・ID解決）では既存英語キー経路を維持する。
- **実装前に参照元を確認する**: 対象文字列を変更する前に、`grep` 等で比較・照合・ID解決の参照箇所を洗い出し、表示専用変更で閉じる設計にする。

### Oracle 本文の運用ルール（2026-05 追加）
- **1行 80 バイト未満を厳守**: `src/rumors.c` の `outoracle()` は `line[COLNO]`（`COLNO=80`）で読み出すため、`dat/oracles.txt` 本文行と `util/makedefs.c` の `special_oracle[]` 各行は UTF-8 バイト長で 80 未満に保つ。
- **区切り行は変更しない**: `-----` はレコード境界なので、文字数・位置・行の独立性を維持する。
- **地名訳は既存実装に合わせる**: `The Dungeons of Doom` は `src/dungeon.c` の表示語彙に合わせて **運命の大迷宮** を用いる。

## 6. 推奨ワークフロー

1. 未翻訳メッセージを抽出する。
2. 最初は小さな単位で適用する。
3. 次にやや複雑な処理を実施する(識別子の数や並びの変更、メッセージ組み立て処理の変更など)
4. 実際にゲーム実行時に組み立てられるメッセージが自然な日本語になることを確認する。不自然であればさらに修正する。
4. ビルド（手順は `.github/copilot-instructions.md` 参照）でエラーがないか確認する。
5. 可能であれば実機で `--More--` や表示崩れを確認する。

## 8. 百科事典(dat/data.base)の翻訳知見

### 構文維持ルール
- **構造の厳守**: 行頭の検索キー（空白なし）と、説明文行（TABで始まる行）の構成を維持する。
- **引用元の維持**: `[ ... ]` で始まる引用行は、表記を含めてそのまま維持する。
- **改行**: 全角34文字を目安に改行し、日本語として自然な場所で折り返す。

### 効率的な翻訳手法（一括置換）
- **辞書ベースの置換**: 大規模な翻訳漏れには、`dat/data.base` の該当箇所をスクリプトで一括処理する手法を推奨する。
- **作業手順**:
    1.  未翻訳行を特定する（`Select-String` 等でTAB開始行かつ日本語なしを抽出）。
    2.  `json` 形式で「英語キー : 日本語値」の辞書ファイルを作成する。
    3.  `Python` スクリプトを使用して、ファイル全体を走査・置換し、バックアップファイル (`.new`) を生成する。
    4.  `diff` で置換内容を確認し、問題なければ上書き適用する。
- **安全第一**: `write_file` による全書き換えは避け、必ず部分置換または検証可能なスクリプトでの適用を行うこと。
- **ビルドの都度確認**: `makedefs` でエラーが出ないか、意図しない行が破壊されていないかを常に確認する。

## 9. ステータスUI 用語辞書と狭幅tty規則（2026-05 追加）

### ラベル方針
- status UI の表示ラベルは **漢字のみ** を優先する。
- 可読性のため、3文字以上になっても許容する。
- GUI/tty は意味を統一し、表示幅に応じた省略のみ差分を許容する。
- OPTIONS 指定や内部参照キー（status-hilite の field/condition 名）は英語を維持する。
- status-hilite の textmatch は旧英語表示指定を受理する互換を維持する。

### 数値系2文字語彙辞書（統一用）
- HP: 体力
- Pw: 魔力
- AC: 防御
- Xp: 等級
- HD: 魔級
- T: ターン
- Gold: 金額
- Dlvl: 階層
- Score: 得点

- Str/St : 筋力
- Int/In : 知力
- Wis/Wi : 賢明
- Dex/Dx : 器用
- Con/Co : 耐久
- Cha/Ch : 魅力


### 狭幅ttyでのラベル省略順（固定）
1. 条件表示の短縮（既存の段階短縮）
2. 低優先度項目のラベルを省略: version, terrain, armor, weapon, time
3. 次点項目のラベルを省略: dungeon-level, gold, AC, Xp, HD, Pw, HP
4. 次に省略: alignment, carrying-capacity, score
5. 最後に能力値6項目（筋力/器用/体力/知力/賢明/魅力）のラベルを省略
6. それでも収まらない場合のみ、encumbrance短縮・Dlvl短縮・最終切り詰めを実施
