# NetHackJP 翻訳作業 指示ファイル

この文書は、NetHackJP の日本語化作業における翻訳方針、スタイル、および実務上の知見をまとめたものです。ビルド手順やプロジェクト管理などの技術的な運用については `.github/copilot-instructions.md` を参照してください。

## 1. 目的と対象

- **目的**: ユーザー向けメッセージの日本語化を、安全かつ一貫性を保って進める。挙動を変えず表示文言のみを改善する。
- **優先対象**: 画面表示されるメッセージ（`You(...)`, `You_feel(...)`, `pline(...)` など）。
- **対象外**: コメント、ログ、内部診断用文言（`impossible(...)`, `error()` など）。
- **README**: `README.JP` は `README` の翻訳とし、プロジェクト進捗などは記載しない。

## 2. 翻訳の基本方針

### 文体・スタイル
- **常体**: 「だ・である」を基本とする。
- **時制**:
  - 叙述は過去形を優先（例: 〜した、〜だった）。
  - 継続的な状態や感覚は現在形（例: 〜している、〜が聞こえる）。
  - 短時間の音・感覚は過去形（〜感じた）、長時間のものは現在形（〜感じる）を推奨。
- **ニュアンス**: 原文の意味を尊重し、過剰な意訳や情報の追加を避ける。

### 記号・表記
- **文末記号**: 互換性のため、半角 `.`, `!`, `?` を維持する。
- **UI整合性**: 既存のUI訳語（職業名・種族名など）と整合させる。

## 3. 用語ルール

### 重要語句の区別
- **boulder**: 巨大な岩
- **rock** (壁・地形文脈): 岩
- **iron bars**: 鉄格子
- **tree**: 木
- **door**: 扉
- **wall**: 壁
- **mortal**: 定命の者

※ 特に **boulder** と **rock** を同じ訳語にしないこと。

## 4. フォーマット指定子の厳守

以下は絶対に変更しない（個数、順序、型、対応する引数式）。
- `%s`, `%d`, `%ld`, `%c`, `%p`, `%l`, `%n`, `%o` など。
- **禁止**: `%s` の削除、型の変更（`%d` → `%ld`）、引数の入れ替え。

## 5. 翻訳の実務知見

- **最終表示文の確認**: 複数のリテラルや分岐で構成される文は、結合後の全体像で自然か確認する。
- **pline系関数**: 文言以外の位置制御や履歴制御（`pline_dir` 等）には触れない。
- **補助関数の活用**: `Monnam()`, `body_part()`, `Tobjnam()` 等の返り値を前提に語順を調整する。
- **接頭辞の自動付与**: `You_hear()`, `You_feel()`, `You_see()` 等は主語を自動付与するため、リテラル側で主語を重複させない。
- **不自然な連結の回避**: `隠し%s` などのテンプレートは、展開後の語（扉、通路等）との連結が自然か確認する。

## 6. 推奨ワークフロー

1. 未翻訳メッセージを抽出する。
2. 小さな単位で適用する（既存英文は削除せず、リテラル置換のみ）。
3. 差分でフォーマット指定子の不変を確認する。
4. ビルド（手順は `.github/copilot-instructions.md` 参照）でエラーがないか確認する。
5. 可能であれば実機で `--More--` や表示崩れを確認する。
