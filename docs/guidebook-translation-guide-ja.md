# NetHack ガイドブック翻訳方針および保守・作成手順

本ドキュメントは、NetHack の公式ガイドブック（`Guidebook`）の日本語訳方針、テキスト版と Markdown 版のデュアルフォーマット運用、ビルドスクリプトを用いた生成手順、および保守方法についてまとめたものです。

---

## 1. 概要と構成

NetHack のガイドブックは、新規プレイヤーへのチュートリアルから詳細なコマンド・オプション仕様までを網羅した公式解説書です。  
NetHackJP では、従来の端末・エディタでの閲覧に適した**等幅テキスト版（TXT）**と、スマートフォンや Web ブラウザでの閲覧に最適化した **Markdown 版（MD）**の双方を提供しています。

### ディレクトリ構成
```text
NetHackJP/
├── Guidebook/                      # 配布パッケージに同梱されるガイドブック一式
│   ├── Guidebook.txt               # 英語版ガイドブック（原本 doc/Guidebook.txt のコピー）
│   ├── Guidebook.md                # 英語版 Markdown（レスポンシブ・スマホ最適化）
│   ├── Guidebook_JP.txt            # 日本語版ガイドブック（等幅テキスト、段落折り返し維持）
│   ├── Guidebook_JP.md             # 日本語版 Markdown（レスポンシブ・スマホ最適化）
│   └── images/                     # ガイドブック内で参照される WebP 画像
│       ├── fig1.webp               # 図1: 画面レイアウトサンプル
│       ├── fig2.webp               # 図2: ステータス行レイアウト
│       └── fig3.webp               # 図3: 移動キー配置ダイアグラム
├── doc/
│   └── Guidebook.txt               # アップストリーム原本（ビルド・保守用）
└── docs/
    ├── guidebook-translation-guide-ja.md # 本ドキュメント
    └── scripts/                    # ガイドブック生成・画像化スクリプト
        ├── build_markdown_guidebook.py   # 日英両対応の Markdown 変換スクリプト
        └── generate_guidebook_images.py  # アスキーアートの WebP 画像生成スクリプト
```

## 2. 日本語訳の方針

### 2.1. 用語の統一と対訳基準
- **公式対訳テーブルとの完全一致**:
  - モンスター名、アイテム名、アーティファクト名などの固有名詞は、NetHackJP リポジトリ内の公式対訳データ（`src/mon_jp.c` の `mon_jp_name[]`、`src/objects.c` の `jp_item_name()` 等）、および用語集リファレンス（`glossary_references/obj_jp.txt`, `mon_jp.txt`）の訳語と完全に一致させてください。
- **代表的な定訳**:
  - `Sokoban` ➔ 「**倉庫番**」（「ソコバン」等のカタカナ表記は禁止）
  - `Genocide` ➔ 「**虐殺**」（「根絶」等へのブレを防止）
  - `Dungeoneers` ➔ 「**ダンジョニア**」

### 2.2. 直訳調・不自然語尾の排除
- **「〜のだった」等の冗長語尾の排除**:
  - 物語調・説明文において「〜のだった」「〜だったのだった」という冗長な文末を排除し、シンプルで自然な表現（「〜した」「〜していた」等）を選択してください。
- **カタカナ「アンド」の排除**:
  - 英語の `and` を機械的に「アンド」と直訳することを禁止し、文脈に応じて「そして」「また」「〜と」「および」などに置き換えてください。
- **指示代名詞の機械翻訳誤訳（「色」等）の排除**:
  - `it` や `this` が「色」と直訳されている箇所を排除し、本来の文脈に応じた指示代名詞（「これ」「それ」等）や名詞へ修復してください。
- **不自然な一人称の回避**:
  - カタカナ表記の「ワタシ」を避け、自然な日本語（「私」「自分」等）を使用してください。

### 2.3. 二重フォーマットの品質要件
- **テキスト版 (`Guidebook_JP.txt`)**:
  - オリジナルの `doc/Guidebook.txt` が持つ段落の折り返し幅、段落先頭の 5 文字インデント、改ページフッター・ヘッダー等の等幅テキストレイアウトを忠実に維持してください。
- **Markdown 版 (`Guidebook_JP.md`)**:
  - 段落内の不要な改行やインデントを排除し、段落全体を 1 つのテキスト行として自然に連結してください。
  - 日本語文字間（ひらがな、カタカナ、漢字等）の余分な空白を排除し、英単語間の空白は適切に維持してください。

## 3. Markdown 版の最適化ルール

スマートフォン等の縦長画面でも横スクロールや表示崩れを起こさず、快適に閲覧できるようにするため、以下の変換ルールをスクリプト（`docs/scripts/build_markdown_guidebook.py`）により一貫して適用します。

### 3.1. アスキーアートの WebP 画像化と折りたたみテキスト併記
- 横幅の広い画面サンプルやキー配置図は、等幅フォントレンダリングによるダークスタイル（#1e1e1e 背景・明色文字・枠線付き）の高画質 WebP 画像（`images/fig*.webp`）へ置換します。
- 画像の直下には `<details><summary>テキスト版（アスキーアート）を表示</summary>` を併記し、必要に応じて元テキストを確認・コピーできるようにします。

### 3.2. テキストブロックの Markdown 表（テーブル）化
- 横幅が広くスマホで折り返されやすい一覧表は、Markdown テーブル構文へ変換します：
  - **7.5 防具**: `| 鎧（防具） | AC値 |`
  - **9.15 記号の変更**: `| 記号 | 記号名 | 説明 |`
  - **12.2 ダンジョニア**: `| ダンジョニア | ダンジョニア | ダンジョニア |`（3列テーブル）

### 3.3. オプション名・キー名・設定パラメータのリスト構造化
- 9.4（一般オプション）、9.5（ウィンドウポート）、9.6（クラッシュレポート）、9.7（プラットフォーム固有）、9.10（キー割り当て）に加えて、以下のセクションについても本文と結合していたパラメータ名を分離・インデント構造化します：
  - **9.17 視覚障害者向け設定**: `symset:plain`、`menustyle:traditional`、`number_pad` などの 16 設定パラメータを `- **設定名**\n\n  説明文` 形式でリスト化。
  - **9.18 システム管理者向け設定 (sysconf)**: `WIZARDS`、`SHELLERS`、`MAXPLAYERS` などの 22 パラメータを `- **パラメータ名**\n\n  説明文` 形式でリスト化。

### 3.4. 設定例・構文例のコードブロック化
- `autopickup_exception="<*arrow"`, `BIND=...`, `OPTIONS=...`, `MSGTYPE=...`, `MENUCOLOR=...`, `SOUND=...` などの設定例を網羅的に検出し、独立した ````text ... ```` コードブロックに整形します。
- **9.14 ステータス強調表示設定**: 「強調表示の例:」（英語: `Examples of status hilites:`）の直後に続く `OPTION=hilite_status: ...`（10行）も ````text ```` コードブロックで囲み、本文と明確に区別します。

### 3.5. Markdown 見出し誤認（行頭 `#`）の防止
- 第4章の `#extended_command`（`#adjust`, `#loot` 等）が行頭にあると Markdown の見出し（H1）として解釈されてしまうため、`- `#command` : 説明` のリスト形式へ確実に変換し、見出し誤認を完全に防止します。

### 3.6. roff 引用符（`... '）から Markdown インラインコード（`...`）への自動変換
- NetHack の原本（roff 形式）では、コマンドキーやオプション名の引用に伝統的な引用符 `` `... ' ``（開きバッククォート、閉じアポストロフィ）が多用されています（例: `` `u' ``, `` `B' ``, `` `fixinv' `` 等）。
- これをそのまま Markdown に出力すると、Markdown パーサーがバッククォートをインラインコードの開始・終了として交互に解釈し、本文全体が等幅ハイライトになる反転表示崩れを引き起こします。
- スクリプト（`build_markdown_guidebook.py`）により、以下の変換を一貫して自動適用します：
  - **一般の引用符**: `` `u' `` ➔ `` `u` ``、`` `fixinv' `` ➔ `` `fixinv` ``（Markdown インラインコード構文）
  - **バッククォートキー（`）自体の引用**: `` ``' `` ➔ `` `` ` `` ``（CommonMark 規格のダブルバッククォート構文）
  - **バックスラッシュ記号（\）の引用**: `` `\\' `` ➔ `` `\` ``
  - **二重引用符**: `` ``word'' `` ➔ `"word"`
  - **オプション値内のバッククォート**: `invorder` などの文字列 `")[%?+!=/(*`0_"]"` は `` `` [%?+!=/(*`0_"] `` `` へエスケープ。

## 4. 更新・生成手順（保守ワークフロー）

### 4.1. アップストリーム追従時の更新手順
1. アップストリーム（本家 NetHack）で `doc/Guidebook.txt` に変更が入った場合、変更差分を確認します。
2. `doc/Guidebook.txt` を `Guidebook/Guidebook.txt` にコピーします：
   ```powershell
   Copy-Item "doc/Guidebook.txt" -Destination "Guidebook/Guidebook.txt"
   ```
3. 差分に対応する日本語訳を `Guidebook/Guidebook_JP.txt` に反映します（等幅レイアウトを維持）。

### 4.2. 画像ファイルの再生成（必要な場合）
アスキーアートの内容が変更された場合、画像生成スクリプトを実行して WebP 画像を更新します：
```powershell
python docs/scripts/generate_guidebook_images.py
```
> ※ Pillow (`pip install Pillow`) が必要です。

### 4.3. Markdown ファイルの自動生成
Markdown 変換スクリプトを実行して、日英両方の Markdown ファイルを更新します：
```powershell
# 日英両方を生成
python docs/scripts/build_markdown_guidebook.py

# 日本語のみ生成する場合
python docs/scripts/build_markdown_guidebook.py --lang jp

# 英語のみ生成する場合
python docs/scripts/build_markdown_guidebook.py --lang en
```

### 4.4. 生成結果の検証
スクリプト実行後、以下の項目が満たされていることを検証します：
1. **見出し誤認チェック**: コードブロック外の行頭 `#` が 0 件であること。
2. **画像・折りたたみタグの一致**: 画像リンク（3箇所）および `<details>` と `</details>` の開閉数が一致していること。
3. **テーブル構文**: 各テーブル行の構文崩れがないこと。

## 5. CI / リリース成果物への同梱

GitHub Actions ワークフロー（`.github/workflows/weekly-release.yml`）により、週次ビルド時に `Guidebook/` ディレクトリ全体が配布 ZIP パッケージに自動同梱されます：
- **Windows 配布物**: `NetHackJP-5.0.1-*-windows.zip` 直下の `Guidebook/` に格納。
- **Linux 配布物**: `NetHackJP-5.0.1-*-linux.zip` 内の展開ディレクトリ直下の `Guidebook/` に格納。
