# NetHackJP `dat/data.base` 日本語翻訳計画

## 1. 目的
`dat/data.base` ファイル内のゲーム内百科事典の記述を、NetHack の世界観と引用元の雰囲気を尊重しつつ、自然な日本語に翻訳する。
以前、ファイルを破壊した経験を踏まえ、今回は安全かつ非破壊的な手法で作業を完遂する。

## 2. 基本方針
*   **翻訳のベース**: 既存の日本語版 NetHack の `data.base` を参考にし、文学作品の引用は公式訳を尊重。新規項目は雰囲気に合わせて新訳を作成。
*   **文体**:
    *   文学的引用: 原文の雰囲気・既訳を尊重。
    *   科学的説明: 客観的な「〜である」調。
    *   ジョーク: ユーモアを活かした自然な日本語。
*   **構文の厳守**:
    *   検索キー行（行頭空白なし）と説明文行（`TAB` 開始）の構造を維持。
    *   `#` コメント行はそのまま。
    *   プレースホルダは削除・変更禁止。
    *   折り返しルール:
        *   **散文（通常の文）**: 原文の英文行が半角70〜80文字程度で構成されている長い行については、日本語の翻訳文も既存のルール通り**1行あたり全角30～34文字（最大34文字）**の範囲内で美しく折り返します。
        *   **ポエムや歌、短い対話などの短文形式**: 元の英文がポエムや歌のように短い文で構成されており、改行位置が元々短い場合は、日本語訳もそのオリジナルの改行形式とリズムに合わせて短い行で適切に改行します。
*   **引用元の翻訳**:
    *   説明文の末尾にある `[ ]` で囲まれた引用元（書籍名や著者名等）も、元の英文から自然な日本語に翻訳して適用する（例: `[ Dracula, by Bram Stoker ]` → `[『ドラキュラ』、ブラム・ストーカー著 ]`）。その際、行頭のインデント等、元の構文フォーマットは崩さずに厳守する。

## 4. 安全な編集のための鉄則（最重要）
**以前の教訓: ファイルの構造や順序を崩さず、文字コードの混在を防ぐこと。**

1.  **直接編集の禁止**: `write_file` によるファイル全体の上書きは絶対に行わない。
2.  **置換ツールの使用**: `replace` ツールを使用し、変更対象のブロックのみを正確に指定する。
3.  **1項目（1キー）ずつの順序処理**:
    *   データの並び順が崩れるのを防ぐため、また作業を確実にコントロールするため、**1項目（1キー）ずつ上から順番に**翻訳を適用していく。
4.  **UTF-8 エンコードの徹底統一**:
    *   異なるエンコード（Shift_JIS 等）の日本語が混ざることによるファイル破壊を防ぐため、記述する日本語はすべて **UTF-8** で完全に統一する。
5.  **確認手順**:
    *   対象ブロックを `read_file` または `grep_search` で取得し、空白や改行コードを含む正確なテキストを把握する。
    *   `replace` を実行し、0件ヒットの場合は強制せず、対象テキストの確認からやり直す。
    *   実行後に `git diff` で意図しない箇所が変更されていないか必ず確認する。
6.  **バックアップ**: 大きなブロックを編集する際は、念のため一時ファイルに作業内容を保存してから実行する。
7.  **前回の成果物の再利用禁止（クリーンスタートの徹底）**:
    *   前回の失敗を完全に排除するため、前回作成されたスクリプトや一時ファイルは一切再利用しない。必要に応じて、完全に一から設計・作成し直す。
8.  **手戻り防止（差分の保護と極小化）**:
    *   1項目（1キー）の翻訳が完了し、検証（`git diff` と `makedefs`）が成功した段階で、**即座に `git add dat/data.base` を実行して差分をステージング（保護）**する。これにより、万が一別の箇所で問題が発生し `git restore` 等の巻き戻し操作を行う際にも、すでに成功した他の翻訳が巻き添えで消失するのを防ぐ。
    *   いかなる巻き戻し・修正操作を行う場合も、実行前後に必ず `git status` および `git diff` を確認し、他の正常な翻訳項目に影響が及んでいないかを厳重に検証する。
9.  **助詞「の」が英単語「of」に化ける不具合への対策**:
    *   長い日本語テキストの新規置換時、特定の処理エンジンや推論フィルタの影響で、日本語の助詞「の」が英単語の `of` に誤変換されて出力される不具合が確認されている。
    *   置換後は**必ず `git diff` で「of」が紛れ込んでいないかを入念に目視チェック**する。
    *   もし `of` への誤変換を検知した場合は、即座に該当行のみを対象としたピンポイント置換（`replace_file_content`）を重ねて実行し、正しい「の」へと修正・復旧させる。この不具合が完全に解消された状態になってから、`makedefs` 検証および `git add` による差分保護へ進む。

## 5. ワークフロー
1.  次に対象とするキーブロックを特定する。
2.  対象範囲を `read_file` で取得し、正確な文字列を確認する。
3.  翻訳文を作成する。
4.  `replace` ツールで翻訳を適用する。
5.  `git diff` で差分を検証する。
6.  `dat/` ディレクトリにて `..\tools\Debug\x64\makedefs.exe -d` を実行し、エラーが発生しないこと（makedefs処理が正常に完了すること）を確認する。
7.  検証が完了した時点で、`git add dat/data.base` を実行して差分をステージ（保護）する。
