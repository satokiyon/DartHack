# Stage B 手動確認ケース（Windows日英入力両対応）

この文書は、Stage B（願い/名称解析の日英両対応）で追加した入力受理を手動で再確認するための固定ケース集です。

## 前提

- 対象ビルド: Debug x64（NetHack, NetHackW）
- 対象入力: 自由文字列入力（主に wish 系）
- 期待方針:
  - 既存英語入力は従来どおり受理される
  - 日本語入力は追加語彙を受理する
  - 単文字入力の仕様には影響しない

## 実行メモ

- 可能なら同一セッションで英語入力と日本語入力を対で実施する。
- 失敗した場合は、入力文字列をそのまま記録する（前後空白も含む）。
- 受理成否だけでなく、生成された対象（種別・内容）を確認する。

## ケース一覧

### 1. 祝福/呪い/無呪プレフィックス

1. `blessed long sword` -> 受理（既存英語の非回帰確認）
2. `祝福されたロングソード` -> 受理
3. `祝福の ロングソード` -> 受理
4. `呪われたロングソード` -> 受理
5. `呪われているロングソード` -> 受理
6. `無呪ロングソード` -> 受理
7. `呪われていないロングソード` -> 受理

### 2. 日本語モンスター名フォールバック

1. 日本語モンスター名のみ入力（例: 各ロールで確認しやすい代表種）
2. 英語モンスター名入力（対照確認）
3. 日本語名 + 後続語（空白区切り）

期待:
- 英語既存一致を壊さない
- 英語未一致時に日本語名が解決される

### 3. figurine / statue / corpse 文脈

1. `オークの人形`
2. `人形のオーク`
3. `オークの石像`
4. `石像のオーク`
5. `オークの死体`
6. `死体のオーク`

期待:
- 文脈ごとに対象種別が適切に選ばれる
- `像` 系は statue 側へ寄る（figurine と衝突しない）

### 4. tin 基本語彙

1. `tin of spinach`（英語非回帰）
2. `ほうれん草の缶詰`
3. `空の缶詰`
4. `ランダムの缶詰`
5. `オーク肉の缶詰`

期待:
- spinach / empty / random の特殊内容が正しく反映される
- `〜肉` がある場合でも対象モンスター解決に成功する

### 5. tin 調理語（日本語）

1. `酢漬けのオーク肉の缶詰`
2. `燻製オーク肉の缶詰`
3. `炒めたオーク肉の缶詰`
4. `ソテーのオーク肉の缶詰`
5. `ピューレのオーク肉の缶詰`

期待:
- 調理語が `tin_variety` に反映される
- 調理語を除いた残りで内容モンスターが解決される

### 6. tin 調理語同義語（Step 9+10）

1. `自家製のオーク肉の缶詰`
2. `腐っているオーク肉の缶詰`
3. `フライドオーク肉の缶詰`
4. `茹でオーク肉の缶詰`
5. `炙り焼きオーク肉の缶詰`
6. `すり潰しオーク肉の缶詰`

期待:
- 同義語入力が既存種類へマップされる
- `の` と空白の有無で受理がぶれない
