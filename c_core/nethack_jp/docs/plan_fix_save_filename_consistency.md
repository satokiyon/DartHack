# セーブファイル名の属性情報付加の修正案

## 目的
新規ゲーム開始時の初回セーブにおいて、セーブファイル名に職業・種族・性別・属性（サフィックス）が含まれない問題を修正します。これにより、復元後のセーブ動作と一貫性を持たせ、同じキャラクター名でも異なる属性のキャラクターを区別しやすくします。

## 鍵となるファイルとコンテキスト
- `src/role.c`: キャラクターの役割（Role）や属性等の初期化を担当。`role_init()` 関数で最終的な属性が確定します。
- `src/files.c`: セーブファイル名の生成（`set_savefile_name()`）を担当。`svp.plname` を元にファイル名を構築します。
- `include/decl.h`: `svp.plname` や `gp.plnamelen` などのグローバル変数を定義。

## 実施手順

### 1. src/role.c の修正
`role_init()` 関数の末尾に、`svp.plname` に属性サフィックスを追加するロジックを挿入します。

- `gp.plnamelen` が 0（サフィックス未設定）かつ、キャラクター名が設定されている場合に処理を行います。
- `gu.urole.filecode`, `gu.urace.filecode`, `genders[]`, `aligns[]` を使用してサフィックス（例: `-Hum-Hum-Mal-Law`）を構築します。
- `PL_NSIZ` (32バイト) の範囲内で `svp.plname` に連結します。
- `gp.plnamelen` に元の名前の長さを格納します。
- サフィックス追加後、`set_savefile_name(TRUE)` を呼び出して、そのセッションで使用されるセーブファイル名 `gs.SAVEF` を更新します。

### 2. 検証
- 新規ゲームを開始（例: 名前 "test"）し、一度セーブして終了する。
- セーブファイル名が `test-職業-種族-性別-属性.NetHack-saved-game` になっていることを確認。
- 再起動し、そのセーブデータを復元して再度セーブする。
- ファイル名が変わらず、一貫性が保たれていることを確認。
- 非常に長い名前を入力した場合に、バッファオーバーフローが発生せず、サフィックスが付かない（または安全に切り詰められる）ことを確認。

## 影響範囲
- `svp.plname` が変更されるため、ゲーム内でのキャラクター名の表示（「test-Hum... は...」など）にサフィックスが含まれるようになります。これは NetHack 3.6/3.7 において復元後に発生する挙動と同じであり、本プロジェクトの運用方針に合致すると判断します。
- スコアファイル（record, logfile）の名前欄にもサフィックスが含まれるようになります。
